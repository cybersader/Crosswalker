## Anchored to the implemented constructs — not ad-hoc

The harness must **converge on the real, already-built ingestion constructs**, not grow its own logic. The transformation/ETL design was settled in the 2026-05 design phase ([schema-as-primitive](/crosswalker/concepts/etl-and-import/), RML/YARRRML-retargeted recipe + JSONata expression layer, the closed 5-mechanism grammar) — and a code investigation (2026-06-03) confirmed what's **live in `src/`**:

| Construct | Status | The harness should use it for |
|---|---|---|
| **`spec/recipe.schema.json`** — import recipe (`source.levels`, `target.layout[]`, `also_emit`, `graph_edges` reserved) | ✅ implemented + AJV-validated | the per-framework "config" **is a recipe** — not CLI flags |
| **`render(recipe, identity) → Address`** (pure; folder/file/heading wired, tag/wikilink fail-fast in v0.2) | ✅ implemented (`src/render/`) | compute path / frontmatter / tags / aliases — instead of the harness's own `buildFrontmatter` |
| **`generateFromRecipe(app, data, recipe, …)`** | ✅ implemented (`src/generation/`) | the native recipe import path (Obsidian-bound — the headless harness calls the **pure `render()`** + writes via `fs`) |
| **Template filters** `lower \| upper \| title \| slug \| tagsafe \| fs-safe \| truncate(N)` | ✅ closed set (`src/render/template.ts`) | recipe-expressed transforms (R2RML `{var\|filter}`) |
| field-split (regex/split), merged-cell forward-fill, the ~40-primitive catalog, JSONata-in-templates | ❌ design-only | **the logic we build up** as real frameworks demand it |

**The retarget:** the harness's `--map` / `--sheet` / `--header-row` are an *ad-hoc stand-in*. The disciplined path is: parse source → build `ConceptIdentity[]` → feed a real **Recipe** (`spec/recipe.schema.json`) through the implemented **`render()`** → write Tier 1. Each snag then **extends the real filter set / primitive catalog** — building up reusable ETL logic against first-principles constructs, which is the entire point of running the corpus in practice.

## The harness (the rapid loop)

`tools/generate-fixtures.ts` — a headless `bun` CLI: **source file → Tier 1 concept notes** (schema-conformant), deterministic, drift-gated, **no Obsidian**. The fast iteration surface is: *point at a real file → inspect the notes → tweak the config → rerun (seconds)*. It started CSV-only with hard-coded columns; this log tracks its growth into a multi-format, config-driven importer — driven entirely by what real frameworks demand.

## Capabilities built

### `--map` — config-driven column mapping · 2026-06-02

- **Snag:** the harness hard-coded canonical column names (`id`, `description`); real frameworks use their own (`identifier`, `control_text`) → **0 rows matched**.
- **Fix:** `--map "srcCol=role,…"` aliases a framework's real columns onto the canonical roles (`id / name / title / family / parent / description`).
- **Result:** NIST **800-53 r5** (CSV) went 0 → **1,189 control notes**.

### XLSX reader — `--sheet` + `--header-row` · 2026-06-02

- Built workbook ingestion on the `xlsx` lib: **select a sheet** (by name or 0-based index), **treat a chosen row as the header** (skips banner/preamble rows above it), coerce every cell to a trimmed string → feeds the same pipeline (so `--map` still applies).
- **Result:** NIST **CSF 2.0** (`csf2.xlsx`, sheet `"CSF 2.0"`, header row 1) → **185 subcategory concepts** (the Function/Category group-header rows surface as empty-id and are skipped).

## Snags surfaced (the live backlog)

Running real frameworks *is* the requirements process. What's surfaced so far:

| Snag | Seen on | What's needed |
|---|---|---|
| **Combined id + text cells** — `Subcategory` = `"DE.AE-01: Adverse events are analyzed…"` (code + name in one cell) | CSF 2.0 | a **field-split** transform: regex-extract the leading code → `id`, the remainder → `title` / `description` |
| **Merged-cell forward-fill** — Function/Category sit only on group-header rows; empty on the child rows → `family` blank | CSF 2.0 | forward-fill hierarchy columns down into child rows (then group-headers can become parent concepts too) |
| Empty-id rows skipped silently | 800-53, CSF | acceptable default; consider a `--strict` skipped-row report |
| Per-framework invocation is a long CLI string | all | promote `--map` / `--sheet` / `--header-row` into a **config file** — the Tier-3 "as-code" unit |

## Next — retarget onto the implemented constructs

1. **Refactor the harness to call the real `render()` + a `Recipe`** (`spec/recipe.schema.json`) — drop the bespoke `buildFrontmatter`/`buildBody`. The per-framework config becomes a recipe JSON, validated against the schema. This is the load-bearing move: everything below rides on it.
2. **field-split** → add a `split` / `regex-extract` **template filter** (extends the implemented closed set in `src/render/template.ts`): code → `id`, remainder → `title`. (Many frameworks pack code + name in one cell, e.g. CSF.)
3. **merged-cell forward-fill** → a row pre-transform (the cross-structural **forward-fill** primitive) so hierarchy columns (CSF Function/Category, CRI, D3FEND) populate child rows.
4. **Author real recipes** for 800-53 (CSV) + CSF 2.0 (XLSX) under `recipes/` + **golden fixtures** (regression).
5. **JSON reader** (logical source + iterator path) → STIX / OSCAL / CPRT (39 files).
