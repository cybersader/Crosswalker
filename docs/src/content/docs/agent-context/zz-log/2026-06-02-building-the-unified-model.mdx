## Why this log exists

The [foundations log](/crosswalker/agent-context/zz-log/2026-06-01-unified-control-model-ontological-foundations/) gave us the categories (objective, risk, obligation, control, audit/finding), the three useful lenses (Control / Assurance / Risk), the name, and the field landscape. **None of that is a *built* model yet — it's the blueprint.** This log turns the blueprint into something real:

1. **The Tier 1 schema** — concrete entity types, attributes, and typed edges (the buildable contract).
2. **The worked model** — the entities + relationships as an actual graph you can populate.
3. **The first crosswalk** — one real proving-ground crosswalk end-to-end through Crosswalker.

## Schema deltas — the starting point

Falling directly out of the foundation: the entity types, attributes, and edges the model needs. *(Draft — reconcile against [`spec/tier1.schema.json`](/crosswalker/agent-context/v0-1-schema-spec/) before committing; let the proving ground below confirm the minimum set rather than over-designing.)*

### Entity (node) types

| Entity | Key attributes (beyond identity) | From the foundation |
|---|---|---|
| **Objective** | — | the teleological root (what everything serves) |
| **Risk** | `inherent`, `residual`, `treatment` (avoid / transfer / mitigate / accept), `appetite_band` | the risk lens |
| **Obligation** | `authority_source` (internal-governance / external-regulatory / contractual) | obligation ≠ compliance |
| **Control** | `function_type` (preventive / detective / corrective / directive), `design_status`, `operating_status` | the control + assurance lenses |
| **Finding** | `severity`, `status` (open / remediated / accepted), `engagement_id` | audit — the one genuinely new first-class node |
| **Asset · Vendor · Process · Evidence · Incident** | carried from the existing unified-model entity set | shared entities |

### Edge (relationship) types

| Edge | Between | Carries |
|---|---|---|
| `satisfies` | control → obligation | — |
| `mitigates` | control → risk | effectiveness |
| `concerns` | finding → control / risk / obligation | — |
| `evidences` | evidence → control | status / freshness |
| `requires` | obligation → control | — |
| **crosswalk** | concept ↔ concept (framework ↔ framework) | STRM relation + SSSOM confidence / justification |

**No privileged node** — "spine" is a profile/view, not a structural fact (per the foundation). Control-/risk-/obligation-centric are *query lenses* over this one graph.

## Build plan

1. **Reconcile** these deltas against the [v0.1 schema spec](/crosswalker/agent-context/v0-1-schema-spec/) — what already exists, what's new, what's the minimum.
2. **Define** the entities + edges concretely (the worked model).
3. **Build the first crosswalk** (proving ground): **NIST CSF 2.0 ↔ 800-53** — both public-domain, both held, and an official NIST concept-crosswalk exists — end-to-end through Crosswalker → render a coverage view.
4. **Let the proving ground drive the schema** — build one real crosswalk; let it reveal which deltas are actually needed instead of designing them in the abstract.
5. **Validate** the foundation + the built model with colleagues; revise.
