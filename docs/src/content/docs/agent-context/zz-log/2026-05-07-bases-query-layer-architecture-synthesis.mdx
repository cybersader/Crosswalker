## §1 Settled (no further debate — convergent across deliverables)

| # | Settled commitment | Source convergence |
|---|---|---|
| 1 | **Hybrid architecture**: Bases as default + SQL/sidecar as escape hatch | Ch 27 a/b/c + Ch 28 a/c |
| 2 | **Single `registerBasesView` for v0.1.6** — `crosswalkerCoverageMatrix` (one custom view, not three) | Ch 27a + Ch 28 a/c |
| 3 | **`_crosswalker/` underscore folder convention** (Obsidian doesn't index dot-folders) | Ch 28 a/c |
| 4 | **Mobile/Publish parity is the binding constraint** (`sqlite-wasm` + OPFS unavailable on Obsidian Mobile via Capacitor; codeblock processors never execute on Publish) | Ch 28 a/c |
| 5 | **`metadataCache.resolvedLinks` for edge resolution** — not string LIKE; not custom projector | Ch 27c + Ch 28 a/c |
| 6 | **Junction-note schema denormalizes `control_id` + `framework` strings** for Bases filtering | Ch 27c + Ch 28 a/c |
| 7 | **Manifest-first [OpenTimestamps](https://opentimestamps.org/) audit model** — one `.ots` per snapshot manifest, not per row | Ch 28 a/c |
| 8 | **Determinism is non-negotiable** for OTS to be meaningful (stable row/key ordering; byte-identical regen) | Ch 28 a/c |
| 9 | **Junctions = audit truth; matrices = caches/projections** — never conflate | Ch 28c explicit + Ch 28a CQRS framing |
| 10 | **Recipe lifecycle**: schema validation + provenance + `user_edited:true` flag + three-way merge | Ch 28 a/c |
| 11 | **TaskNotes v4** is the canonical Obsidian-plugin precedent for "delete bespoke filter UI; let Bases own it" | Ch 27a + Ch 28 a/c |

These are durable across all three plausible architectural framings. **They go into the synthesis verdict regardless of how D1–D6 resolve.**

## §4 What this synthesis WILL lock (once D1–D6 are decided)

A finalized synthesis log will:

| Aspect | Lock |
|---|---|
| Integration mechanism | Single `registerBasesView` (`crosswalkerCoverageMatrix`) for v0.1.6 |
| Folder convention | `_crosswalker/views/` (plugin-emitted `.base` files) + `_crosswalker/audit/` (materialized snapshots, v0.1.8+) |
| Edge resolution | `metadataCache.resolvedLinks` snapshotted into closure cache; refreshed on `changed`/`resolved` events |
| Junction-note schema | 13 fields with denormalized `control_id` + `framework` strings (for Bases filtering); wikilinks for navigation |
| Recipe lifecycle | YAML in `_crosswalker/recipes/`; `id`/`version`/`schema_version` keyed; sources = system/user/community; `user_edited:true` flag; three-way merge for conflicts; JSON Schema validation on save (warn) + on materialize (block) |
| Audit-trail integration | Manifest-first OpenTimestamps; one `.ots` per snapshot manifest; deterministic recipe execution required for OTS to be meaningful |
| Mobile/Publish parity | Bases-only path is the only mechanism that crosses desktop + mobile + (future) Publish; codeblock = desktop+mobile; sqlite-wasm = desktop with in-memory fallback on mobile |
| Architectural framing | CQRS-explicit: query layer ≠ snapshot layer (pending D4 confirmation) |

The deferral table (also pending finalization):

| Phase | What lands |
|---|---|
| **v0.1.6** | Single `registerBasesView` + reference `.base` file on first run + recipe loader + `_crosswalker/` namespace + Bases-disabled fallback |
| **v0.1.7** | `crosswalker-query` codeblock processor + `sqlite-wasm` user-facing surface + recipe wizard UI |
| **v0.1.8** | Materialization (`Reports/_generated/` or `_crosswalker/audit/`) + OpenTimestamps + manifest-first audit + deterministic-output guarantees |
| **v0.2+** | Background/scheduled materialization, three-way merge UI, multi-view custom Bases types, community recipe registry, Bases-on-Publish-specific rendering, mobile sqlite-wasm persistence |
