## What this is

These are **adversarial/exploratory research briefs** — focused assignments that can be handed to a fresh agent with no prior context bias. Each challenge:

- Targets a specific architectural assumption, decision, or design
- Asks the agent to critically assess, stress-test, or find alternatives
- Is grounded in [first principles](/crosswalker/concepts/problem/) and the project's [philosophical pillars](/crosswalker/concepts/what-makes-crosswalker-unique/)
- Thinks long-term and large-scale — not just "does this work today" but "does this hold at 100K notes, 50 frameworks, 10 years from now"

## How to use

1. Pick a challenge from the list below
2. Hand it to a fresh agent (one with no prior conversation context about this project)
3. Point the agent at the KB (`docs/src/content/docs/`) for context
4. Let it research, critique, and report
5. Log findings in [`zz-log/`](/crosswalker/agent-context/zz-log/) if they surface decisions or insights worth preserving

## Why fresh agents

Every agent that works on a project accumulates context bias — it starts agreeing with past decisions because it helped make them. A fresh agent given only the KB and a challenge brief can find blind spots that embedded agents can't see.

### Why these batches were filed

**2026-04-10 (Ch 01-04)** — the original first-principles set: break the diff primitives, stress the architecture at scale, map the competition, audit the KB for sloppy thinking.

**2026-05-03 (Ch 21)** — strictly upstream of Ch 20. Ch 20 settled *what shape* the import primitive takes; Ch 21 asks whether the primitives come from our codebase or someone else's (build / adopt / compose), with opportunity-cost, governance, and sustainability lenses.

**2026-05-07 (Ch 27-28)** — v0.1.6 prerequisites. Bases can't do joins, recursion, anti-joins, or multi-file aggregation; junction notes reify edges as Bases-queryable files but cross-junction aggregation still hits the flat-YAML wall. Ch 27 designs the routing; Ch 28 stress-tests materialization lifecycle, `registerBasesView`-vs-codeblock, mobile/Publish parity, and audit-trail implications.

**2026-05-08 (Ch 29-37)** — the ontology-web alignment review found the synthesis log had drifted GRC-coded and that several v0.1.7+ commitments rested on never-validated assumptions. Ch 29-34 are new questions; Ch 35-37 are **reruns** of archived Ch 10 / Ch 12 / Ch 18 under the ontology-web framing.

> **Rerun convention**: original briefs stay archived as historical record. Each rerun is a NEW brief with a fresh Ch number that anchors to the original as predecessor and frames "what's different now". Original deliverables are preserved verbatim; reruns produce NEW deliverables that may revise prior verdicts.

**2026-06-01 (Ch 39-41)** — pre-ingestion gate for the unified model. The full [security & GRC framework corpus](/crosswalker/reference/framework-corpus/) is assembled, and the unified-model assumptions (most pointedly "is CRI the spine?") were inherited rather than tested. Run roughly in order 39 → 40 → 41.

**2026-06-14 (Ch 42)** — surfaced while making the [system model](/crosswalker/concepts/system-model/)'s `render()` diagram honest: `layout` assumes **known depth**, so variable / ragged-depth hierarchy is not first-class. Current state in the [open-question log](/crosswalker/agent-context/zz-log/2026-06-14-variable-depth-hierarchy-open-question/).

**2026-08-19 (Ch 44)** — filed from the re-entry sprint that landed the July work. Two gaps found while running the gates: plugin E2E never runs in CI, and no screenshot anywhere is diffed against a baseline. Framed deliberately as coverage/detection/cost rather than as a framework comparison.

**2026-07-11 (Ch 43)** — Act 2 of the five-act lifecycle arc ("your ontology updates and your world survives"). The match-pass / impact-pass / review / apply sketch is architect-drafted, not stress-tested against how NIST, MITRE, and CIS actually ship version deltas.
