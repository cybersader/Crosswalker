The generation engine converts the decisions you made in the [import wizard](/crosswalker/features/import-wizard/) into real vault structure: folders, notes, frontmatter, links, and (where the shapes call for it) parent-child links and hub notes.

## Folder creation

Hierarchy columns define the folder tree. For a file with columns mapped as:
- Level 1: `Control Family`
- Level 2: `Control ID`

The engine creates:
```
Ontologies/
├── Access Control (AC)/
│   ├── AC-1.md
│   ├── AC-2.md
│   └── ...
├── Audit (AU)/
│   └── ...
```

## Note generation

Each leaf in the hierarchy becomes a markdown note with:

### YAML frontmatter
All frontmatter-mapped columns become properties:
```yaml
---
control_id: AC-2
control_name: Account Management
family: Access Control
_crosswalker:
  source: nist-800-53.csv
  imported: 2026-04-02T12:00:00Z
  config: my-nist-config
---
```

### Body content
Body-mapped columns are inserted as markdown text below the frontmatter.

### Links
Link-mapped columns generate WikiLinks. Multiple values (comma-separated) create multiple links.

## Connected output

Beyond the note-by-note conversion above, an import built through the [live mapping workbench](/crosswalker/features/import-wizard/#map-the-shapes) or a [built-in configuration](/crosswalker/agent-context/ui-lexicon/) can also come out already connected:

- **Children lists** — when your data has a clear parent/child id relationship, a parent note gets a managed `children` property listing its child notes. Re-importing keeps this list current without touching anything else you've written on the note.
- **Hub notes** — a column with a handful of shared values (a category, a tactic, a domain) gets its own note per value, listing every note that carries it. Content you write below the hub note's heading survives a re-import; only the list itself is managed.

This is currently limited to the live mapping workbench and built-in-configuration paths — the classic Step 2 column table doesn't produce children lists or hub notes yet. The [review screen](/crosswalker/features/import-wizard/#review-and-confirm) shows a link count before you generate, so a disconnected import is visible up front either way.

## Key naming

Frontmatter keys are transformed based on your naming style setting:

| Style | Input | Output |
|-------|-------|--------|
| As-is | `Control Name` | `Control Name` |
| Lowercase | `Control Name` | `control name` |
| Snake case | `Control Name` | `control_name` |
| Camel case | `Control Name` | `controlName` |
| Kebab case | `Control Name` | `control-name` |

## Metadata tracking

Every generated note includes `_crosswalker` metadata so you can:
- Identify which import created the note
- Re-import without duplicating
- Track import history
