You need Crosswalker [installed and enabled](/crosswalker/getting-started/installation/) and a framework file to import: a CSV, XLSX, or JSON export of controls, requirements, or techniques.

## Import your first framework

1. **Open the Crosswalker workspace tab.** Click the network-shaped ribbon icon, click the status bar count, or run **Crosswalker: Import structured data** from the command palette (`Ctrl/Cmd + P`). You can also right-click a CSV, XLSX, or JSON file in the file explorer and choose **Import into vault with Crosswalker**, which skips straight to configuring it.

2. **Pick your file.** For example, a NIST 800-53 controls export. Large CSVs stream in, so multi-megabyte files are fine. For XLSX you also pick the worksheet and header row; for JSON you pick which list of records to import.

3. **Take the fast path if it's offered.** When your file's columns match a framework Crosswalker already knows (NIST CSF 2.0, NIST 800-53, MITRE ATT&CK, CIS Controls v8, the Secure Controls Framework, CRI Profile, and crosswalk files), a **Recognized source** card appears with a summary of what it found. Choose **Import with this configuration** to accept it, or **Customize** to adjust it first.

4. **Otherwise, map your columns.** Tell Crosswalker what each column is for: which ones become folders, which become note titles, which become note properties, which become links to other notes, and which become body text. A live preview on the right shows a real folder tree and one fully rendered note, updating as you change things.

5. **Review and confirm.** The review screen shows the destination folder, a recap of every mapping, how many notes, folders, and links you'll get, and a plain-language warning if some rows don't fit the pattern you built.

6. **Generate.** Crosswalker writes the folders and notes into your vault.

Full detail on every screen is on the [import wizard](/crosswalker/features/import-wizard/) page.

## What you get

Folders and one note per row, under your output folder (`Ontologies` by default):

```
Ontologies/
└── NIST-800-53/
    ├── AC-1.md
    ├── AC-2.md
    ├── AC-2(1).md
    └── AU-1.md
```

Each note carries your mapped columns as Obsidian properties, links to related notes, and a small record of where it came from:

```yaml
---
curie: "nist-mini:AC-2(1)"
title: Automated System Account Management
aliases:
  - AC-2(1)
tags:
  - framework/nist-mini/ac
family: AC
family_name: Access Control
control_id: AC-2(1)
parent: "[[AC-2]]"
_crosswalker:
  spec_version: "https://crosswalker.dev/spec/tier1.schema.json"
  source_ref:
    file: nist-mini.csv
    source_hash: sha256-380a762cd51be31c9f5d71ef8725a7863d3d07055a54e22dc5be3776088eac8a
  produced_at: "2026-05-04T00:00:00.000Z"
  producer:
    kind: plugin-engine
    name: crosswalker-plugin
    version: 0.1.0
---

# Automated System Account Management

## Description

Support the management of system accounts using automated mechanisms.
```

The `_crosswalker` block is how a re-import recognizes its own notes, so it updates them rather than creating duplicates. See the [generation engine](/crosswalker/features/generation-engine/) for exactly what lands in each note.

:::caution[What a re-import preserves, and what it does not]
This depends entirely on the **existing-file mode** you choose in the import wizard.

| Mode | Effect on a note that already exists |
|---|---|
| **Skip existing** (the default) | The note is left completely untouched. Nothing you wrote is at risk |
| **Replace** | The note is **rebuilt from the source row**. Frontmatter keys you added are merged back, but **anything you typed into the note body is overwritten and not recoverable** |
| **Error** | The import stops rather than touching the existing note |

So: keep your own writing — evidence links, analysis, commentary — in **separate notes** that link to the generated ones, not inside the generated notes themselves. Generated folders are best treated as importer-owned and disposable.

Verified against `src/generation/generation-engine.ts` on 2026-08-19: in Replace mode the note content is rebuilt and written without reading the existing body.
:::

## Where the settings are

Everything configurable lives in **Settings > Crosswalker**: the output folder, how property names are cased, how multi-value cells become lists, link style, how eagerly saved configurations are suggested, and the toggle for the live mapping workbench under **Import behavior**. See the [settings reference](/crosswalker/reference/settings/).
