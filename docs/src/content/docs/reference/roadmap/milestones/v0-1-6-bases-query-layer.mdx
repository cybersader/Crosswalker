Move the v0.1 output query layer from Dataview to [Bases](/crosswalker/concepts/metadata-ecosystem/) (Obsidian's official structured-data query system). Update the templates that the plugin emits — [concept-note](/crosswalker/concepts/terminology/) query examples, [evidence-link](/crosswalker/concepts/terminology/) aggregations, coverage-matrix views — so they work natively in Bases without requiring users to install Dataview. Per the [project memory commitment](/crosswalker/agent-context/zz-log/2026-05-04-import-engine-design/) (saved 2026-05-04).

<Aside type="caution">
This milestone's scope (translate Dataview-shaped templates → Bases-shaped) understates the architectural design work. Bases CAN'T do joins, recursion, anti-joins, or multi-file aggregation — exactly the queries users want for compliance/crosswalk views. **Resolve [Ch 27](/crosswalker/agent-context/zz-challenges/27-bases-query-layer-architecture/) + [Ch 28](/crosswalker/agent-context/zz-challenges/28-bases-query-layer-followon-stress-test/) first**; the consolidating synthesis log will refine v0.1.6 scope before code starts.
</Aside>

## Scope

**In:**
- Bases-shaped query templates the plugin emits in concept-note bodies (e.g., "Controls in this family", "Evidence covering this control")
- Updated docs / starter recipes referencing Bases (not Dataview)
- Compatibility check: Tier 1 frontmatter shapes (concept_note, junction_note, crosswalk_edge) are queryable in Bases without restructure

**Out:**
- Building a Bases plugin / extension — Bases is upstream Obsidian; we just emit queries that Bases can run
- Custom Bases views beyond what Obsidian ships
- Datacore as backup option (defer; may revisit if Bases proves limited)

## Concrete tasks

- [ ] Audit existing query templates in `src/generation/` and `recipes/starter/` for Dataview-style notation; list every occurrence
- [ ] Translate each query template to Bases-shape (covered in `.claude/skills/obsidian-bases/`)
- [ ] Verify Tier 1 frontmatter keys (`tags.contains()`, `file.hasTag()`) work as expected with Bases — note Obsidian's Bases querying nested-tag-prefix via `file.hasTag()` per Ch 22 §1.3
- [ ] Update generation-engine templates that get inserted into concept-note bodies on import
- [ ] Update KB pages — `concepts/metadata-ecosystem`, `getting-started/grc-teams`, `features/import-wizard` — to show Bases examples
- [ ] Add a "Querying your imported framework" page under `features/` showing common Bases queries against Tier 1 output

## Success criteria

- [ ] Every emitted concept-note body that contains a query renders as a working Bases view in Obsidian
- [ ] No Dataview-specific syntax (`dv.pages()`, `inline:: value`, `WHERE`, `FROM`) appears in plugin-emitted output
- [ ] User can answer the canonical questions ("What evidence covers AC-2?", "Which ISO controls map to NIST AC family?") via Bases without installing extra plugins
- [ ] Coverage matrix view (one row per control, columns showing crosswalks to other frameworks) renders in Bases
