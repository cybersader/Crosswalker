## Goal

Implement the [Tier 2](/crosswalker/concepts/terminology/) [sidecar projector](/crosswalker/concepts/embedded-vs-server-substrates/) — the deletable, recoverable SQLite projection of [Tier 1](/crosswalker/concepts/terminology/) frontmatter. Auto-projects on vault load; lazy closure cache for transitive [crosswalk](/crosswalker/concepts/terminology/) queries; if `.crosswalker.sqlite` is missing/corrupted/stale, reproject from canonical Tier 1 on next load. Per [Ch 24 substrate synthesis](/crosswalker/agent-context/zz-log/2026-05-04-tier-2-substrate-synthesis/) (sqlite-wasm + sqlite-vec; libSQL/Turso/Limbo rejected).

## Scope

**In:**
- Bundle `@sqlite.org/sqlite-wasm` + `sqlite-vec` into the plugin (custom-static-link build per Ch 24 §2.4)
- Project Tier 1 frontmatter on vault load — populate `mappings`, `junction_notes`, `concepts`, `ontologies` tables
- Lazy closure cache — recursive-CTE-derived transitive closure, materialized on demand
- Recovery on missing/stale sidecar — reproject from Tier 1; abort + warn if Tier 1 itself is malformed
- OPFS persistence via `opfs-sahpool` VFS (works on Capacitor without COOP/COEP — the mobile-portable path)
- Runs on main thread with cooperative yielding (Web Workers unreliable per Ch 23 §9.5)
- `Platform.isDesktopApp` gate where needed (e.g., for full XLSX read on the mobile path; not v0.1.5 concern but design accordingly)

**Out:**
- DuckDB-WASM / Oxigraph / Nemo (researched back-pocket per [v0.1 stack pivot](/crosswalker/agent-context/zz-log/2026-05-02-v0-1-initial-stack-pivot/))
- Tier 3 server (deployment-guide concern; v2.0+)
- libSQL / Turso / Limbo (rejected per [Ch 24 synthesis](/crosswalker/agent-context/zz-log/2026-05-04-tier-2-substrate-synthesis/))
- Vector-search UI in v0.1.5 — schema and storage only; query UI lands in v0.1.6 or v0.2

## Concrete tasks

- [ ] Custom WASM build of `@sqlite.org/sqlite-wasm` with `sqlite-vec` statically linked (per `sqlite-vec-wasm-demo` pattern)
- [ ] New `src/tier2/sidecar.ts` — wraps the WASM, manages OPFS-backed `.crosswalker.sqlite` lifecycle
- [ ] DDL for `mappings`, `junction_notes`, `concepts`, `ontologies` tables (matches Tier 2 SQL section in v0.1 schema spec)
- [ ] Projector — `projectFromTier1(vault) → void`: scan vault frontmatter, upsert into sidecar tables
- [ ] Recovery semantics — if sidecar missing or schema-version mismatch, reproject from Tier 1
- [ ] Lazy closure cache — `closure_cache` table; populated on first transitive query; invalidated on Tier 1 changes
- [ ] Query API — typed `query()` exports for v0.1.6/v0.1.7 to consume
- [ ] Cooperative yielding — chunk projection work; `await new Promise(setTimeout)` between batches; yield back to UI thread
- [ ] Bundle-size budget — measure post-static-link WASM size; target ~600 KB compressed (per Ch 24 §2.2)
- [ ] Unit tests — round-trip projection (project, modify Tier 1, reproject, query); recovery test (delete sidecar, reload, verify auto-reprojection)
- [ ] Mobile sanity check — open `test-vault/` on Obsidian Mobile (iOS or Android); confirm sidecar projects and queries succeed via `opfs-sahpool` VFS

## Success criteria

- [ ] Sidecar projects 100K mappings in under 30s on a typical desktop (per Ch 18 scale ceiling)
- [ ] Deleting `.crosswalker.sqlite` and reloading the vault cleanly reprojects without user action
- [ ] Recursive-CTE transitive closure query (e.g., "all controls that NIST CSF Identify maps to via any chain") returns results consistent with Tier 1 facts
- [ ] Bundle size: plugin core + sqlite-wasm + sqlite-vec ≤ 1.2 MB compressed
- [ ] Sidecar functions on Obsidian Mobile (Capacitor WebView) via `opfs-sahpool` VFS

## Open questions
